Question file format

You can write a question file for QBank by hand, or ask an AI chat to write it.

A question file is one set of questions for the app, written as JSON.

The app checks a file before importing it, and lists every error and warning it finds. An error blocks the import; a warning does not.

The file may wrap its JSON in a Markdown code fence; the check reads the JSON inside it. A file that is only a list of questions is a practice set titled "Imported questions".

An example

A complete file, which the check takes with no error and no warning:

{
  "title": "Basic geography",
  "desc": "A capital, a river, and bodies of water.",
  "questions": [
    {
      "id": "g1",
      "type": "single",
      "ask": "What is the capital of France?",
      "options": [
        {
          "t": "Paris",
          "ok": true,
          "why": "Paris is the capital of France and its largest city."
        },
        {
          "t": "Lyon",
          "why": "A large city, but not the capital."
        },
        {
          "t": "Marseille",
          "why": "A major port, but not the capital."
        }
      ],
      "rationale": "The French government sits in Paris."
    },
    {
      "id": "g2",
      "type": "single",
      "ask": "True or false: the Nile flows north.",
      "options": [
        {
          "t": "True",
          "ok": true,
          "why": "The Nile runs north into the Mediterranean Sea."
        },
        {
          "t": "False",
          "why": "Rivers run downhill, whichever way that is."
        }
      ]
    },
    {
      "id": "g3",
      "type": "order",
      "ask": "Put these in order from smallest to largest.",
      "items": [
        {
          "t": "Pond"
        },
        {
          "t": "Lake"
        },
        {
          "t": "Ocean"
        }
      ],
      "rationale": "Lakes are larger than ponds, and oceans dwarf both."
    }
  ]
}

The set

FieldRequiredWhat it holds
titlenoThe set's name, as text. "Imported questions" when the file gives none.
descnoA line about what the set covers, as text.
kindno"practice" or "exam". A practice set is the default; an exam set's questions are asked only on exams.
termsnoThe terms its questions use: an object from each term's key to ["Term", "What it means"]. A question lists the keys it uses in its own "terms".
questionsyesThe questions, a list of at least one.

A question

FieldRequiredWhat it holds
idnoIts id, as text or a number. A question without one is Q1, Q2... by its place in the file.
typeyesIts format: one of the question types below.
topicnoWhat it is about, as text. Results are counted by topic.
cjnoThe thinking step it tests, as text, such as a nursing question's clinical judgment step. Missing it is a warning when another question in the file has it.
neednoThe area it belongs to, as text, such as a nursing question's client need. Missing it is a warning when another question in the file has it.
diffnoHow hard it is, as a whole number. Missing it is a warning when another question in the file has it.
wknoThe folder it belongs in, as text, when that is not the set's own.
stemnoWhat comes before the question: the scenario, the passage, the readings. Empty when left out.
askyesThe question itself.
rationalenoWhy the answer is right, shown once the question is answered. Empty when left out.
takeawaynoThe one thing to remember, shown with the rationale. Empty when left out.
termsnoThe keys of the set's "terms" it uses, as a list.
srcnoWhere it comes from, as text: a slide, a page, a line. Missing it is a warning when another question in the file has it.
twinOfnoIn an exam set, the id of the practice question it is the exam twin of. A practice set does not read it.
tablenoA table under the stem, for readings such as vital signs or lab values (see Tables and images).
imagesnoUp to 4 images (see Tables and images).

A question may carry other fields as well: they are kept with it as written.

Question types

The fields of each type's answers:

single: Single answer

  • options: At least 2; exactly one has "ok": true. Each { "t": its text, "ok": true on the right one, "why": why it is right or wrong }.

priority: Priority / first action

  • options: At least 2; exactly one has "ok": true. Each { "t": its text, "ok": true on the one to do first, "why": why it comes first or does not }.

sata: Select all that apply

  • options: At least 2; at least one has "ok": true, and every one may. Each { "t": its text, "ok": true on every right one, "why": why it is right or wrong }.

highlight: Highlight

  • segments: At least 3. The passage in phrases, in reading order, each { "t": the phrase, "ok": true on one to highlight, "why" }; at least one has "ok": true and at least one does not. The phrases are joined with spaces.

order: Ordered response

  • items: At least 3. Each { "t": a step, "why" }, listed in the right order. The app shuffles them.

match: Matching

  • pairs: At least 2. Each { "l": a left item, "r": its match, "why" }.
  • extra: Optional: right-hand choices that match no left item, each { "r", "why" }.

matrix: Matrix

  • columns: The column names, at least 2, each different.
  • rows: At least 1. Each { "t": its text, "ans": the name of its one right column, "why" }.
  • A column named "both", "either", "either class", "all", "all of these", or "all of the above" (any case) is a warning: a row that fits more than one column belongs in a matrixmulti.

matrixmulti: Matrix, check all that fit

  • columns: The column names, at least 2, each different.
  • rows: At least 1. Each { "t": its text, "ans": a list of the names of its right columns, each once, "why" }; every row has at least one right column, and not every box in the table is right.
  • Its ask should say that a row can fit more than one column, in the words "more than one"; one that does not is a warning.

cloze: Drop-down cloze

  • cloze: { "text": the passage with {0}, {1}... where the blanks go, "blanks": one per placeholder, each { "opts": its choices, at least 2, "ans": the index of the right one from 0, "why" } }.

Tables and images

A question may show a table under its stem, and images. Every screen draws them, so the check refuses one that a screen cannot draw. Use a table for readings, never a picture of one.

table:

FieldRequiredWhat it holds
captionnoA caption, as text.
headnoThe header row, a list of cells.
rowsyesThe rows, a list of at least one, each a list of cells. A cell is text, a number, true or false, or null for an empty cell.

images: a list of at most 4, each:

FieldRequiredWhat it holds
altyesA short description of what it shows.
srcnoThe image itself, as a base64 data URL such as data:image/png;base64,...: PNG, JPEG, WebP, or SVG.
svgnoSVG markup, as text: a diagram drawn for the question.
captionnoA caption, as text.
atno"stem" or "rationale": under the stem (the default), or with the rationale once the question is answered.

Exactly one of src and svg carries the image: PNG, JPEG, WebP, or SVG, at most 300 KB. An image travels inside the file; a link to an image elsewhere is not one. SVG markup may not have a script, an event handler, or a link to another file. at is "stem" or "rationale".
